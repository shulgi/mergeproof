THE WORKFLOW

Three inputs. One proof.

Use files you already own and a small JSON map that connects each printed label to a source column.

.CSV

Source rows

Keep the original CSV with a unique ID for every record. Leading zeros and case are preserved.

.PDF

Final proof

Export with selectable text. Put one record on each page with a visible ID and a standalone end marker.

.JSON

Field map

Pair printed labels with CSV columns. Run --show-text to see the labels MergeProof reads.

LOCAL QUICKSTART

Run your first proof.

Install Node.js 22 or newer and Poppler, then clone the repo and run the sample. Once the prerequisites are installed, the quickstart takes under two minutes.

Read the full documentation Report an issue

Install Poppler

brew install poppler

Clone and run the sample

git clone https://github.com/shulgi/mergeproof.git
cd mergeproof
npm ci
npm run sample
npm run proof:clean

Expect PASS: 0 findings. Try npm run proof:broken to see a failing proof. You can also download the ZIP and run the commands from the extracted source folder.

BEFORE YOU PRINT

Know what a pass means.

What does MergeProof check?

It compares the text for each mapped field against the source CSV. It reports duplicate IDs, missing or unknown records, and pages it cannot verify. Fonts, layout, colour, images, barcodes, and scanned text still need a separate visual proof.

Does it need InDesign?

No. Use any producer that saves a native-text PDF with the supported record layout. MergeProof works from the PDF, CSV, and field map.

Can I run it in a script or agent workflow?

Yes. Use --json for machine-readable results. Exit 0 means a clean text check, exit 1 means findings, and exit 2 means unusable inputs or invocation. Keep visual approval with a person.

Are my files uploaded?

The CLI reads your files on your machine. This page only shows captured sample results and has no upload controls or analytics.
