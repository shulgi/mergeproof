MergeProof

Check the text of a merged variable-data PDF against the CSV that supplied it, record by record. You get a list of physical pages to look at.

Download source.zip Unpacks into a folder called source. See the quickstart to run it.

The job

You ran a data merge (statements, letters, badges, certificates) and exported the final PDF. Before it goes to print, someone has to confirm that every row of the CSV made it onto exactly one page, and that the names, addresses and amounts printed on that page are the ones in the data.

MergeProof does that comparison from the two files you already have: the PDF with live text and the CSV. It reads the record ID on each page, joins it to the matching CSV row and compares the fields you choose. It does not need the layout file or the application that produced it.

  • Wrong or missing field values, with the expected and found text
  • Duplicate IDs printed on more than one page
  • Unknown IDs printed but not in the CSV
  • Missing IDs: CSV rows that never appeared on a valid page
  • Pages it could not verify: no extractable text, a missing boundary, or two records on one page

No account, upload, AI model or telemetry is involved. Your files stay on your computer and are only read.

A small map tells MergeProof which printed labels go with which CSV columns:

map.json{
  "idColumn": "Member ID",
  "idLabel": "Member ID:",
  "endMarker": "END OF RECORD",
  "fields": [
    { "label": "Name:", "column": "Full Name" },
    { "label": "Address:", "column": "Mailing Address" },
    { "label": "Postcode:", "column": "Postcode" },
    { "label": "Plan:", "column": "Plan" },
    { "label": "Balance:", "column": "Balance" }
  ]
}

The clean sample has the same six records in a different order. It passes with exit status 0:

Pages without a record (not findings): 1

Add --json to get the same findings as one JSON object, for scripts and agents. Exit status 0 means the text matched. It is not an approval to print.

Local quickstart

You need macOS or Linux, Node.js 22 or newer, and Poppler's pdftotext:

# macOS (Homebrew)
brew install poppler
# Debian / Ubuntu
sudo apt-get install poppler-utils

MergeProof is installed from source, not from npm. Download the source archive:

Download source.zip

Unpack it. You get a folder called source that contains the README and everything else. Run all the commands below inside that folder. If you have a Git checkout instead, run them in the checkout folder.

cd source               # or your Git checkout
npm ci                  # installs the one dependency, csv-parse
npm run sample          # writes the synthetic samples to samples/
npm run proof:clean     # exit 0: PASS
npm run proof:broken    # exit 1: the 10 findings above

npm prints extra error lines after proof:broken because the exit status is 1. That is expected.

Running it on your own job

  1. Prepare the template. Put one record on each page, a visible ID line such as Member ID: 00042, a field label at the start of each line you want checked, and a closing line with only an end marker such as END OF RECORD.
  2. Export the PDF with live text. Outlined or scanned text cannot be read.
  3. See what MergeProof reads. node bin/mergeproof.js --show-text --pdf "final merged.pdf" lists each page's extracted text, so you can copy your labels exactly.
  4. Write the map and check it. Add --map map.json to the same command. Label lines are tagged, and each page shows whether a record was found.
  5. Run the proof. node bin/mergeproof.js --csv data.csv --map map.json --pdf "final merged.pdf"

If none of your labels are found on any page, the report ends with a hint telling you so, rather than just listing every row as missing.

What the beta supports

Supported

  • One CSV and one PDF with native (selectable) text per run
  • At most one record per page, opened by an ID label and closed by a standalone end-marker line
  • Field values inline or on following lines, including multiline addresses
  • UTF-8 CSV with or without a BOM, quoted commas, doubled quotes and line breaks
  • Exact IDs: leading zeros, case and interior spaces all count
  • Unicode NFC normalization and whitespace collapsing for field values, with no fuzzy matching
  • Text and JSON reports, and exit codes 0 (clean), 1 (findings) and 2 (unusable input)
  • macOS and Linux with Node.js 22+ and Poppler

Not checked

  • Fonts and font substitution
  • Visual design, layout, colour and images
  • Overset, clipped or overlapping text
  • Barcodes and QR codes
  • Scanned pages or OCR
  • More than one record per page
  • Arbitrary templates without an ID label and end marker
  • Windows

MergeProof checks text, so keep your visual proof. An independent clean-checkout test on macOS (Apple silicon) with Poppler 26.04 ran all 101 tests on Node.js 22.23.5 and 26.0.0, and they passed on both. That testing used the synthetic samples. Linux and real production exports have not been verified yet. If font or layout checks would decide whether you use it, tell us which ones in a GitHub issue. That feedback shapes what comes next.
